# Streak

A personal health tracker for one or two people (calories and macros from meal photos or text,
workouts, weight, Apple Watch data, analytics), built as vanilla-JS ES modules with no framework
and no bundler. It runs on the owner's own Cloudflare account (Workers + D1 + Cloudflare Access)
with private per-person storage that syncs across devices. Deploying it is in `SETUP.md`.

## Rules

- Always run wrangler via `npm run cf -- …`, so it uses the project-local login in
  `.wrangler-home/` rather than whatever Cloudflare account is logged in globally on the machine.
- `wrangler.jsonc` is gitignored and holds the deployment's own IDs. `wrangler.example.jsonc` is
  the committed template — when a config key is added, add it there too.
- Secrets (`ANTHROPIC_API_KEY`, `ACCESS_ADMIN_TOKEN`) are Cloudflare secrets, never files. The
  Claude key is read only by the Worker; nothing that reaches the browser may ever carry it.
- `worker/assets.mjs` is generated by `scripts/build.mjs`; never edit it. `npm test` builds first,
  then runs `node --test`.
- Use design-system classes only (`DESIGN.md`, `web/design/tokens.css`, approved reference
  `web/design/preview.html`); add tokens to `tokens.css` first if something is missing.
- No personal data in the repo: no real email addresses, account IDs or deployment URLs in
  committed files. Examples use `example.com`.

## Layout

- `web/`: static modules served by the Worker. Screens are tabs in `index.html`: Today
  (`today-view.mjs`), Log (`meals.mjs`, `meal-editor.mjs`, `photo.mjs`), Workouts (`workouts.mjs`,
  `workout-math.mjs`), Analytics (`analytics-view.mjs`, `analytics-data.mjs`, `charts.mjs`), and
  Settings behind the avatar (`settings-view.mjs`, `about-view.mjs`, `health-view.mjs`,
  `import.mjs`). `shell.mjs` owns tabs and the shared date picker; `store.mjs` has shared helpers;
  `sync.js` handles the local cache and server sync.
- `worker/`: `index.mjs` routes; `records.mjs` stores records in D1; `meal-photo.mjs` and
  `workout.mjs` make the server-side Claude calls (key in the `ANTHROPIC_API_KEY` secret, daily
  cap `PHOTO_DAILY_LIMIT`, token counts logged as `event: meal_estimate`); `health.mjs` handles
  Apple Health; `auth.mjs` checks Access; `people.mjs` holds the allow list (`ALLOWED_EMAILS` plus
  guests the owner invites in Settings → People, stored in D1) and rewrites the Access policy's
  emails using the `ACCESS_ADMIN_TOKEN` secret.
- Typed and dictated meals also go to Claude (`/api/meal-estimate`); the local parser in
  `nutrition.mjs` is the offline fallback.
- Apple Health: an iPhone Shortcut posts daily totals to `/ingest/health` with a per-person
  `dct_…` key (hash in `health_tokens`). That path has its own Access bypass app and the Worker
  checks the key instead. The only other paths that skip Access are the app icons and
  `app.webmanifest` (`PUBLIC_ASSETS` in `worker/index.mjs`), because phones fetch them without
  cookies when saving a home-screen shortcut. Keep both lists in step. Health data is stored as
  `health:YYYY-MM-DD` records and is not writable via `/api/records`.
